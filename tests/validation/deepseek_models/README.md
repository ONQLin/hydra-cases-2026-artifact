# DeepSeek models and complete-length workload replay

Detailed reports and synthetic inputs are generated by the commands below;
only compact historical observations are retained here. New output belongs in
ignored `output_sanity_checks/` directories.

This stage prioritizes model correctness, dependency/memory accounting and
complete selected requests. Multi-fidelity validation is a small integration
smoke test. See the [DeepSeek contract](../../../docs/workload_modernization/deepseek/README.md)
and [Kimi contract](../../../docs/workload_modernization/kimi/README.md).

For capacity expansion with ordinary package sizes, use the newer
[multi-package validation](../multi_package/README.md). The 64-HBM single-mesh
results below remain a separate capacity example.

## Reproduce

Run from the repository root using the HYDRA environment (`myenv/bin/python`
locally). CHIPSIM's existing installation is required only for the three-backend
fixture. All output paths must be fresh.

```bash
# Prepare once and reuse this directory across validation commands.
python tests/validation/prepare_inputs.py \
  --output-dir output_sanity_checks/validation_inputs --include-datasets

python -m unittest tests.test_deepseek_models tests.test_moe_decoder tests.test_mla_streaming
python tests/validation/deepseek_models/profile_models.py \
  --output output_sanity_checks/deepseek/footprints.json

# Minimal three-backend integration / metric-output check.
python tests/validation/modern_models/validate.py \
  --models deepseek-decoder-fixture \
  --trace output_sanity_checks/validation_inputs/kimi_short.csv \
  --require-complete --time-limit 0.05 \
  --output-dir output_sanity_checks/deepseek/fixture

# Actual 61-layer decoder; explicit capacity-feasible hardware override.
python tests/validation/modern_models/validate.py \
  --models deepseek-v3-text --memory-chiplets 64 \
  --trace output_sanity_checks/validation_inputs/kimi_short.csv \
  --backends hydra_sim hydra_packet --require-complete --time-limit 10 \
  --output-dir output_sanity_checks/deepseek/full

# One complete existing Chat request on DeepSeek-V3: input 11 / decode 238.
python tests/validation/modern_models/validate.py \
  --models deepseek-v3-text --memory-chiplets 64 \
  --trace output_sanity_checks/validation_inputs/chat_first1.csv \
  --requests 1 --batch-size 1 --backends hydra_sim --require-complete \
  --time-limit 300 --output-dir output_sanity_checks/deepseek/chat

# Kimi: four complete Chat requests, retaining all 845 decode steps.
python tests/validation/modern_models/validate.py \
  --models kimi-linear-48b-a3b-text-streaming \
  --trace output_sanity_checks/validation_inputs/chat_first4.csv \
  --requests 4 --batch-size 1 --backends hydra_sim --require-complete \
  --time-limit 120 --output-dir output_sanity_checks/model_workloads/chat

# Kimi: one BWB request, input 2331 / decode 1305.
python tests/validation/modern_models/validate.py \
  --models kimi-linear-48b-a3b-text-streaming \
  --trace output_sanity_checks/validation_inputs/bwb_first1.csv --dataset-label bwb \
  --requests 1 --batch-size 1 --backends hydra_sim --require-complete \
  --time-limit 120 --output-dir output_sanity_checks/model_workloads/bwb

# Replay any completed Analytic command to check final request-memory cleanup.
python tests/validation/operator_validation/audit_memory.py \
  --command output_sanity_checks/deepseek/full/deepseek-v3-text/hydra_sim/command.json \
  --output-dir output_sanity_checks/deepseek/memory
```

`--memory-chiplets` records an explicit HBM-count/mesh override; compute chiplet
counts and link bandwidth come from the archived point. The chosen rectangle
honors the existing BW placer's outer-ring HBM policy. It does not perform a DSE
search. `--require-complete` checks every selected request/token and rejects
changed effective input lengths. `--dataset-label` records the actual replay
label independently of the hardware point's original Chat label.

## Model checks

Nine tests cover grouped-router numerical equivalence to an independent oracle,
selection-only correction bias, negative-score masking, group limits and decode
offsets, explicit routing/gather dependencies and tensor bytes, pinned topology,
all-expert weight residency, capacity rejection, single-family heterogeneous
block placement, and consistent expanded-grid configuration/provenance.
Run the unit-test commands above to verify the current implementation.

| Decoder | W8 resident weights (GiB) | State at context 4096, batch 1 (MiB) | Layers |
|---|---:|---:|---:|
| Kimi Linear | 45.05 | 320.94 | 27 |
| DeepSeek-V3 | 623.22 | 137.25 | 61 |

These values exclude activations/workspace. Kimi combines fixed KDA state and
expanded MLA cache; DeepSeek uses absorbed MLA cache. Weight and state requirements
are distinct, and all experts stay resident regardless of active top-k.
`profile_models.py` regenerates the footprint report.

## Existing-dataset replay

| Model / dataset | Requests | HBM count | Prefill / decode steps | HYDRA output tokens | TTFT (ms) | First all-complete checkpoint (s) |
|---|---:|---:|---:|---:|---:|---:|
| Kimi Chat | 4 | 16 | 118 / 845 | 849 | 672.414 | 22 |
| Kimi BWB | 1 | 16 | 2331 / 1305 | 1306 | 1879.251 | 45 |
| DeepSeek Chat | 1 | 64 | 11 / 238 | 239 | 1168.478 | 93 |

All selected requests completed with no preemption. HYDRA counts one prefill
output per request in addition to the requested decode steps. TTFT follows the
existing scheduled-to-prefill-completion convention, excluding initial queue
wait. First all-complete checkpoints are one-second upper bounds, not exact
makespans. Fixed cutoffs (120/300 seconds) include idle time after completion;
their average TP is not a steady-state estimate.
The runner writes metrics, active checkpoints and provenance under `--output-dir`.
The BWB memory audit confirms complete cleanup
at the longest tested context; its final metrics also match the original replay.


These are **complete-length selected requests**, not entire-dataset runs or
steady-state serving benchmarks. Lengths come from the existing Nemotron-tokenized
CSV files; no model-specific retokenization, padding or truncation was performed.
Both models retain synthetic routing and colocated experts. Different hardware
capacities also make this table unsuitable as a direct model-efficiency ranking.

Selection follows source order among requests with positive lengths and total
context <=4096. Chat has 19,965 eligible requests out of 19,975; the first four
source rows are used for Kimi and the first row for DeepSeek. BWB has only
39,244 eligible requests out of 195,522; its first eligible row is index 177
(zero-based). This strong context filtering limits representativeness.
Dataset selection metadata is generated beside each subset CSV, including source row indices and hashes.

Long replays use Analytic. The small fixture establishes three-backend integration;
the short full DeepSeek run checks Analytic/Packet metric output. No long Garnet
run, new network-accuracy study, or calibrated compute claim is part of this stage.
