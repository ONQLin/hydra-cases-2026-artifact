# Multi-package validation

Detailed reports and synthetic inputs are generated by the commands below;
only compact historical observations are retained here. New output belongs in
ignored `output_sanity_checks/` directories.

The subsequent [implementation review and trend study](study/README.md) checks
four-request bursts across 4/6/8 packages and a controlled bandwidth range.
It includes updated tests, cleanup fixes, figures and numerical tables.

[Model and assumptions](../../../docs/multi_package/README.md) ·
[DeepSeek decoder contract](../../../docs/workload_modernization/deepseek/README.md)

Run from the repository root with the HYDRA Python environment active. The
runner selects the existing minimum-TTFT batch-2 Nemotron/Chat design point,
then replicates its **24-node, 6x4 package: 16 x 16-GiB HBMs and eight compute
chiplets**. The original row is preserved in the manifest. This is a capacity
example, not an optimized DeepSeek design or a fixed-compute comparison.

## Reproduce

```bash
# Prepare once and reuse this directory across validation commands.
python tests/validation/prepare_inputs.py \
  --output-dir output_sanity_checks/validation_inputs --include-datasets

# Formula, contention, locality, capacity and corrupted-trace rejection.
python -m unittest tests.test_package_system

# Two layers, two packages, two requests, static batch size 2.
# Each request has 32 prefill tokens and 2 subsequent decode steps.
python tests/validation/modern_models/validate.py \
  --output-dir output_sanity_checks/packages/fixture \
  --models deepseek-decoder-fixture --backends hydra_sim \
  --packages 2 --requests 2 --batch-size 2 --time-limit 0.05 --require-complete

# Full 61-layer decoder, four ordinary packages; no HBM-count override.
python tests/validation/modern_models/validate.py \
  --output-dir output_sanity_checks/packages/deepseek \
  --models deepseek-v3-text --backends hydra_sim \
  --packages 4 --requests 2 --batch-size 2 --time-limit 10 --require-complete

# One complete-length Chat request: 11 prefill + 238 decode steps.
python tests/validation/modern_models/validate.py \
  --output-dir output_sanity_checks/packages/chat \
  --models deepseek-v3-text --backends hydra_sim --packages 4 \
  --trace output_sanity_checks/validation_inputs/chat_first1.csv \
  --requests 1 --batch-size 1 --time-limit 300 --require-complete

# Verify payloads, locality, port serialization and producer/consumer causality.
python tests/validation/multi_package/audit.py \
  --runs output_sanity_checks/packages/deepseek/deepseek-v3-text/hydra_sim \
         output_sanity_checks/packages/chat/deepseek-v3-text/hydra_sim \
  --output output_sanity_checks/packages/audits.json

# Replay the short full decoder and check request-memory reclamation.
python tests/validation/operator_validation/audit_memory.py \
  --command output_sanity_checks/packages/deepseek/deepseek-v3-text/hydra_sim/command.json \
  --output-dir output_sanity_checks/packages/memory
```

For three-backend validation, follow the existing
[Packet](../../../integrations/packet/README.md) and
[CHIPSIM](../../../integrations/chipsim/README.md) setup instructions. Repeat the
**small fixture** command in a fresh directory with
`--backends hydra_sim hydra_packet chipsim_contended`. Paired effective inputs
are checked automatically. Inter-package communication remains analytical on
every backend; this checks execution, not fidelity calibration.

For the slow-link sensitivity case, append
`--package-bandwidth-gbps 0.01 --package-latency-ns 10000` to the Analytic fixture
command, using a fresh directory. Defaults are 25 GB/s, 0.8 efficiency and 1000 ns
startup. Main CLI equivalents are `--package-config.count`,
`--package-config.bandwidth-gbps`, `--package-config.efficiency` and
`--package-config.latency-ns`.

## Measured results

| Case | Packages | Backend | Completed requests | TTFT (ms) | Process wall (s) |
|---|---:|---|---:|---:|---:|
| Decoder fixture | 2 | Analytic | 2 | 0.033 | 1.77 |
| Decoder fixture | 2 | Packet | 2 | 0.392 | 1.77 |
| Decoder fixture | 2 | CHIPSIM/Garnet | 2 | 0.392 | 8.33 |
| Full DeepSeek smoke | 4 | Analytic | 2 | 3249.999 | 13.44 |
| Fixture, slow link | 2 | Analytic | 2 | 1.073 | 2.67 |
| Full DeepSeek Chat | 4 | Analytic | 1 | 1168.490 | 132.32 |

The three small backends complete six output tokens and **10 package transfers /
8,720 bytes**, including four 4-byte token-feedback messages. Packet and Garnet
each drain all 654 local flows. Payloads and producer-transfer-consumer ordering
are checked in smoke audits. The slow-link fixture
raises Analytic TTFT from 33 us to 1073 us with the same requests, mappings and bytes.

The full decoder uses **4 x 256 GiB** HBM with weights split across stages, not
replicated four times. The Chat replay is one complete-length selected request,
not the full dataset. Lengths are inherited from the existing tokenizer trace.
Its **955 package transfers / 5,355,448 bytes** pass the
Chat audit. The short full-model replay also passes
memory cleanup.

Fixed-window TP is 120 tokens/s for the 0.05-s fixture, 0.6 tokens/s for the 10-s
full-model smoke, and 239/300 tokens/s for Chat. These windows include idle time;
they do not establish sustainable throughput. TTFT retains HYDRA's scheduling-
to-prefill-completion definition and excludes initial queue wait. Wall times
include startup, profiling, simulation and output; each was measured once under
concurrent load.

The historical single-package regression reproduced its metrics exactly. Source hashes and manifests are generated with each run. Raw logs remain
under ignored `output_sanity_checks/packages/`; curated evidence is retained here.
