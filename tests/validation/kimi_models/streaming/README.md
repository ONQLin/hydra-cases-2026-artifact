# Streaming MLA and longer-request validation

Detailed reports and synthetic inputs are generated by the commands below;
only compact historical observations are retained here. New output belongs in
ignored `output_sanity_checks/` directories.

Measured on 2026-10-04. This stage adds an explicit serial online-softmax
schedule to the [Kimi decoder contract](../../../../docs/workload_modernization/kimi/README.md).
The historical materialized model/results remain available. New factory names:
`kimi-linear-48b-a3b-text-streaming` and `kimi-decoder-streaming-fixture`.
All comparisons retain shared HYDRA compute, static mapping and disabled DMA
pacing unless the network microcase explicitly enables it.

## Reproduce

Run from the repository root with the installed HYDRA Python environment
(`myenv/bin/python` locally); use fresh output directories. CHIPSIM requires its
separate environment and local socket access, as in the existing integration.

```bash
# Prepare once and reuse this directory across validation commands.
python tests/validation/prepare_inputs.py \
  --output-dir output_sanity_checks/validation_inputs --include-datasets

python -m unittest tests.test_mla_streaming
python tests/validation/kimi_models/profile_mla.py \
  --output output_sanity_checks/kimi_streaming/profiles.json

# Three backends, all 27 decoder layers, two requests with input 2 / decode 2.
python tests/validation/modern_models/validate.py \
  --models kimi-linear-48b-a3b-text-streaming \
  --trace output_sanity_checks/validation_inputs/kimi_short.csv \
  --time-limit 1 --output-dir output_sanity_checks/kimi_streaming/full

# Eight simultaneous requests, input 128 / decode 4, smaller three-layer fixture.
python tests/validation/modern_models/validate.py \
  --models kimi-decoder-streaming-fixture \
  --trace output_sanity_checks/validation_inputs/kimi_concurrent.csv \
  --requests 8 --arrival-interval 0 --time-limit 0.05 \
  --output-dir output_sanity_checks/kimi_streaming/burst

python tests/validation/kimi_models/audit_timing.py \
  --directory output_sanity_checks/kimi_streaming/burst/kimi-decoder-streaming-fixture \
  --output output_sanity_checks/kimi_streaming/burst_timing.json

# Real Garnet and C++ network stress, without HYDRA's microsecond rounding.
.chipsim-venv/bin/python tests/validation/packet_validation/validate_network.py \
  --garnet --stress --quanta 256 1024 \
  --output-dir output_sanity_checks/kimi_streaming/network

# Existing Chat lengths, complete requests; no padding, scaling or truncation.
python tests/validation/kimi_models/prepare_trace.py \
  --source dataset/chat/chat1m_stats_nemo.csv --requests 2 \
  --output output_sanity_checks/kimi_streaming/chat.csv
python tests/validation/modern_models/validate.py \
  --models kimi-linear-48b-a3b-text-streaming \
  --trace output_sanity_checks/kimi_streaming/chat.csv \
  --requests 2 --batch-size 1 --arrival-interval 0.01 \
  --backends hydra_sim hydra_packet --require-complete --time-limit 120 --run-timeout 3600 \
  --output-dir output_sanity_checks/kimi_streaming/chat
python tests/validation/operator_validation/audit_memory.py \
  --command output_sanity_checks/kimi_streaming/chat/kimi-linear-48b-a3b-text-streaming/hydra_sim/command.json \
  --output-dir output_sanity_checks/kimi_streaming/chat_memory
```

`--require-complete` rejects changed lengths, missing rows, or a cutoff before
all requests/tokens complete. The generated trace and its provenance sidecar contain source row indices and SHA-256.
The source has 19,975 requests; 19,965 fit the positive-length, 4096-token
contract. The first two eligible requests are 11+238 and 26+339 tokens. These
are inherited Nemotron-tokenizer lengths, not Kimi-retokenized text. Batch 1
supports heterogeneous requests without inventing a padding policy. This is a
**complete-length two-request replay**, not a full-dataset or agentic benchmark.

## Memory and operator correctness

Seven MLA tests cover online-softmax graph execution against a dense numerical
oracle, expanded/absorbed cache equivalence with shared weights, partial tiles,
causal prefill/decode, extreme logits, batch/head tails, cache bytes and append
ordering, explicit SRAM failure, retained Q liveness and model factory dispatch.
The complete HYDRA suite passed **80 tests with 3 skips** (83 discovered). The
separate CHIPSIM environment passed all **8 tests**, including real Garnet and
DMA. The three HYDRA skips are the existing opt-in Garnet tests and isolated
CHIPSIM-service module; they are not skipped MLA checks.

Twenty analytical cases cover Kimi expanded and DeepSeek-shaped absorbed MLA,
prefill 64/512/1024/4096 and decode context 4096, both algorithms. At synthetic
256 MAC/ns, 16 element operations/ns, 64 SRAM bytes/ns, 1 MiB SRAM and
128 GB/s HBM, batch 1, Kimi-shaped prefill gives:

| Input tokens | Materialized activation peak (MiB) | Streaming activation peak (MiB) | Materialized HBM traffic (MiB) | Streaming HBM traffic (MiB) |
|---:|---:|---:|---:|---:|
| 512 | 64.00 | 8.28 | 208.52 | 82.02 |
| 1024 | 256.00 | 16.56 | 677.27 | 176.27 |
| 4096 | 4096.00 | 66.25 | 9537.77 | 1581.77 |

These are whole-operator liveness/traffic values, including projections and
outer HBM staging; persistent cache is separate. The streaming core's maximum
private workspace here is **189 KiB** (64-query, 128-key, one-head tiles), with
Q pinned across key tiles. No full score matrix is allocated. Streaming uses
FP32 inner probabilities versus the old A8 cast, and still uses aggregate
analytical rates; the results are not a calibrated FlashAttention speedup.
`profile_mla.py` regenerates these operator records.

A review caught Q being released too early in the initial SRAM bound. The fix
has an independent byte-count regression test, and the burst was rerun afterward.
The full decoder replay had already started. A retained
[audit](../audit_query_retention.py) verifies **378 shapes** covering every replay
context plus admission shapes: execution phases, full MLA activation reservation
and decoder admission are unchanged, and both versions fit 1 MiB. The original
run hashes remain in their manifests; the correction is documented rather than
rewriting provenance; the audit script records the checks in its output.

checked effective workload, configuration, hardware/mapping and network causality.
These are single wall-time samples under concurrent host load.

The raw phase audit shows why equal TTFT needs qualification:

| Case | Paired phases | Phases with different raw network timing | Maximum raw timing difference | Rounding / summed phase time |

Rounding totals sum all executed phases, including concurrent work; they are
**not TTFT critical-path attribution**. The full short trace had only one active

Thirteen raw-network cases retain finer timing and include adverse contention.
They use a 2-by-2 mesh, 128-bit links at 1 GHz, eight Garnet VCs and 16 KiB
Packet buffers; these mechanism tests use a different topology from the serving
hardware. DMA cases use 1 GB/s HBMs and 1024-byte bursts.

| Case | Max per-flow completion error vs. Garnet, 256-byte quantum | 1024-byte quantum |
|---|---:|---:|
| Isolated | 0% | 0% |

Smaller packet quantum does not guarantee improvement under staggered fan-in.
Packet supports approximate trends and feedback checks; these results do not
justify a universal accuracy bound. Use real Garnet for contention-sensitive
points. All backends share compute assumptions. Network records.

## Complete-length Chat replay

The 27-layer decoder executes both selected requests through all 577 requested
decode steps; HYDRA also counts one prefill output per request. The long replay
uses Analytic and Packet. Garnet coverage in this stage is the short full decoder,
concurrent fixture and raw-network stress cases above.

| Backend | Completed requests | Output tokens | TTFT (ms) | Process seconds | First all-complete checkpoint (s) |
|---|---:|---:|---:|---:|---:|
| Analytic | 2/2 | 579 | 486.993 | 169.14 | 15 |
| Packet | 2/2 | 579 | 517.962 | 759.26 | 19 |

Packet TTFT is 6.36% higher. At the matched 10-second active
checkpoint, Analytic emits 401 tokens (40.1 tokens/s) and Packet emits
327 (32.7 tokens/s). Packet completed all 3,626,217 submitted flows,
with peak 2 active flows and no in-flight work at cutoff. Both runs passed the
strict completion/length check and paired-input verification. First all-complete
checkpoints bound completion to one-second resolution; they are not exact makespans.
Replay metrics/checkpoints, manifest,
Chat memory audit, burst memory audit.

The fixed 120-second window includes idle time after the requests finish, so
its 4.825 tokens/s should not be read as sustainable throughput. Selected active
checkpoints and the first all-complete checkpoint are retained with the metrics.
Memory lifecycle audits require zero live request objects, zero outstanding
reservations, and every HBM's used/reserved bytes returning to resident weights.

Before scaling to a large representative benchmark, calibrate compute/precision,
refine phase clock resolution, and use Kimi-tokenized traces and recorded expert
routes. Current MoE routes remain synthetic; experts are colocated and serial.
DeepSeek-shaped MLA is covered at operator level, not a full DeepSeek/DSA model.
