# Kimi decoder implementation validation

Detailed reports and synthetic inputs are generated by the commands below;
only compact historical observations are retained here. New output belongs in
ignored `output_sanity_checks/` directories.

Snapshot: **2026-10-04**, original materialized-MLA baseline. The subsequent
[streaming MLA and longer-request validation](streaming/README.md) preserves these
results and reports the next stage separately. The [execution contract](../../../docs/workload_modernization/kimi/README.md)
describes KDA chunks/tiles, synthetic MoE routes, colocated experts, precision
assumptions, and the 4096-token initial limit. All runs use the same archived
Nemotron hardware point selected by the existing modern-model runner, static
batch size 2, static pipeline mapping, and disabled DMA pacing.

## Reproduce

Use the root HYDRA environment and the existing
[Packet](../../../integrations/packet/README.md) /
[CHIPSIM](../../../integrations/chipsim/README.md) installations. Use fresh output
directories. The local runs used `myenv/bin/python` as `python` below.

```bash
# Prepare once and reuse this directory across validation commands.
python tests/validation/prepare_inputs.py \
  --output-dir output_sanity_checks/validation_inputs --include-datasets

# Operator algebra, route conservation, memory and decoder structure.
python -m unittest tests.test_kda_chunk tests.test_moe_decoder

# 18 KDA scheduling / MoE routing cases at declared synthetic rates.
python tests/validation/operator_validation/profile_kimi.py \
  --output-dir output_sanity_checks/kimi_decoder/profiles

# Actual 27-layer decoder topology; two requests, input 2, decode 2.
python tests/validation/modern_models/validate.py \
  --models kimi-linear-48b-a3b-text \
  --trace output_sanity_checks/validation_inputs/kimi_short.csv \
  --time-limit 1 \
  --output-dir output_sanity_checks/kimi_decoder/full

# Smaller three-layer fixture: eight simultaneous requests, input 128, decode 4.
python tests/validation/modern_models/validate.py \
  --models kimi-decoder-fixture \
  --trace output_sanity_checks/validation_inputs/kimi_concurrent.csv \
  --requests 8 --arrival-interval 0 --time-limit 0.05 \
  --output-dir output_sanity_checks/kimi_decoder/concurrent

# Replay the analytic burst and inspect memory after all requests finish.
python tests/validation/operator_validation/audit_memory.py \
  --command output_sanity_checks/kimi_decoder/concurrent/kimi-decoder-fixture/hydra_sim/command.json \
  --output-dir output_sanity_checks/kimi_decoder/memory_audit
```

The runner verifies paired configuration/workload/mapping and network causality.
It supports `--backends hydra_sim hydra_packet` for faster iteration. Real Garnet
needs local socket access. `kda-chunk-mla-operator-fixture` remains available as
a two-operator diagnostic fixture without FFNs.

The full decoder completed both requests and emitted six HYDRA output tokens
(prefill token included), or 6 tokens/s over the fixed 1 s window. The smaller
burst completed all eight requests and emitted 40 tokens, or 800 tokens/s over
0.05 s. These are **finite-workload completion checks**, not saturation TP.
Packet/Garnet agreement at microsecond resolution does not establish general
network accuracy, nor does either independently validate shared compute costs.
Analytic omits detailed network/access timing and aggregates time rounding;
small primitives magnify these differences. Wall times are single samples.
TTFT uses HYDRA's scheduled-to-prefill-completion convention, excluding the
initial queue wait; it is not client-observed end-to-end latency.

The full-decoder Garnet run was launched separately; its effective inputs,
hardware/mapping and source hashes were checked against the Analytic/Packet run.
The commands above regenerate decoder/fixture metrics and their manifests.

## Operator and memory checks

For Kimi-shaped KDA, prefill 128, batch 1, at **synthetic** 256 MAC/ns,
16 element operations/ns, SRAM 64 bytes/ns and 1 MiB, HBM 128 GB/s:

| KDA implementation | Total modeled HBM traffic (MiB) | Estimated latency (ms) |
|---|---:|---:|
| Previous whole-state recurrent baseline | 563.34 | 34.12 |
| Head-tiled recurrent | 55.34 | 29.93 |
| Head-tiled chunk, size 64 | 55.34 | 29.47 |

The traffic reduction comes from retaining each state tile in SRAM. Chunking
also changes arithmetic and SRAM accesses; it is not assumed universally faster.
Projection/gate traffic remains included. These numbers are cost-model estimates,
not measured silicon/GPU timings. The 18-case export
also covers prefill 32/1024, decode context 4096, and cyclic versus hotspot MoE.
The same total expert weights remain resident in both route scenarios.

The memory audit confirms zero outstanding request
reservations and zero live request objects after the burst; every HBM's used and
reserved bytes return to its resident weights. Cleanup regression tests also
cover multiple state objects on one HBM and isolation from another request.
The full-decoder memory audit independently
confirmed the same reclamation after both full-decoder requests completed.

The final HYDRA suite ran **75 tests: 72 passed, 3 skipped**. Seventeen added tests
cover the KDA and MoE/decoder work. The three skip entries are the two opt-in
Garnet tests and the separately loaded CHIPSIM service module, as documented in
the [earlier validation](../operator_validation/README.md). Full decoder and
concurrent fixture runs above used real Garnet successfully.
The separate CHIPSIM suite also passed all **8 tests**, including real Garnet
contention and HBM DMA pacing.
