# KDA / MLA operator validation

Detailed reports and synthetic inputs are generated by the commands below;
only compact historical observations are retained here. New output belongs in
ignored `output_sanity_checks/` directories.

This checks operator accounting and the shared execution path. It is not a full
Kimi/DeepSeek benchmark. See the [operator audit and execution contract](../../../docs/workload_modernization/operators/README.md)
for supported algorithms, memory assumptions and outstanding model work.

The subsequent [Kimi decoder validation](../kimi_models/README.md) covers chunked
KDA, head/value tiling, colocated MoE and the 27-layer decoder. The results below
retain the original two-operator fixture for comparison.

## Reproduce

From the repository root, activate the HYDRA environment from the root README.
Packet and CHIPSIM setup are in
their respective [Packet](../../../integrations/packet/README.md) and
[CHIPSIM](../../../integrations/chipsim/README.md) READMEs.

```bash
# Graph, arithmetic, dependencies, state, liveness and admission checks.
python -m unittest tests.test_attention_operators

# Twelve model-shaped operator cases; no network or model weights required.
python tests/validation/operator_validation/profile_operators.py \
  --output-dir output_sanity_checks/operator_validation/profiles

# Synthetic KDA -> MLA fixture on one existing Nemotron hardware point.
python tests/validation/modern_models/validate.py \
  --models kda-mla-operator-fixture \
  --backends hydra_sim hydra_packet chipsim_contended \
  --time-limit 0.25 \
  --output-dir output_sanity_checks/operator_validation/serving
```

Use a fresh serving output directory. The runner verifies equal effective
workloads/configuration and completed network traces. It uses two requests,
static batch size 2, input length 32 and two requested decode iterations.
HYDRA counts the prefill-produced token as well, hence six output tokens.
The fixture has `D=512`, one KDA block (`H=8,K=64`) and one absorbed MLA block
(`H=8,Qrank=128,C=64,P=32,R=16,V=32`). There is no FFN, MoE, embedding or LM head.
HBM DMA pacing is disabled.

The operator-only exporter uses explicitly synthetic rates: 256 MAC/ns,
16 element operations/ns, 64 SRAM bytes/ns, 1 MiB SRAM, 128 GB/s HBM and batch 1.
Its 12 cases cover Kimi-shaped recurrent KDA, Kimi-shaped expanded NoPE MLA and
DeepSeek-shaped absorbed MLA, each at prefill 32/128 and decode context 128/4096.
It writes graph tensors/edges, lowered phases and a summary with code hashes.

## Recorded checks (2026-10-04)

| Backend | Fixture TTFT | Process wall time | Completed network flows |
|---|---:|---:|---:|
| HYDRA-Analytic | 47 us | 1.72 s | N/A |
| HYDRA-Packet | 102 us | 1.77 s | 105 / 105 |
| CHIPSIM/Garnet | 102 us | 9.83 s | 105 / 105 |

All runs completed both requests, with 6 output tokens over a 0.25 s observation
window: 24 tokens/s. This is a fixed small workload, **not saturation throughput**.
Both network audits passed with zero flows left in flight; peak concurrent flows
was one, so this fixture does not validate contention under load. Equal Packet
and Garnet TTFT at microsecond resolution is not evidence of general accuracy.
Access latency and per-phase time rounding contribute to their difference from
Analytic. Wall times are single process measurements including setup.

The commands above regenerate operator profiles, serving metrics and manifests
under `output_sanity_checks/operator_validation/`. Unit tests independently
check arithmetic, graph dependencies, state liveness and memory admission.

The HYDRA suite ran **58 tests: 55 passed, 3 skipped** (CHIPSIM-specific environment
or opt-in tests). This includes 12 new operator tests. The separate CHIPSIM suite
passed all 8 tests, including real Garnet, directed writes, contention and DMA:

```bash
python -m unittest discover -s tests
RUN_CHIPSIM_GARNET_TESTS=1 .chipsim-venv/bin/python -m unittest \
  tests.test_chipsim_runtime_service \
  tests.test_chipsim_contention.PacketContentionTest \
  tests.test_chipsim_dma_pacing
```

HYDRA's SimPy clock tests run in the HYDRA environment. The isolated CHIPSIM
environment intentionally does not contain the full HYDRA dependency set.
