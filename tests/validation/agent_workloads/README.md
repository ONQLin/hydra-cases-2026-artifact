# Agent replay validation

Detailed reports and synthetic inputs are generated by the commands below;
only compact historical observations are retained here. New output belongs in
ignored `output_sanity_checks/` directories.

This page retains the initial synthetic validation. The subsequent
[real BFCL replay and tool-profile validation](real_bfcl/README.md) adds archived
Qwen3-8B input, direct Tyro configuration, and host/external tool execution models.

**Synthetic integration evidence, not BFCL benchmark results.** The fixture uses
BFCL's inspected result-log structure with invented content and token counts.
No model generated these fixture logs, and no tool code was executed. Real archived
logs are handled separately by the follow-up above.

See [the integration guide](../../../integrations/workloads/README.md) for ordered
commands, and [the architecture](../../../docs/agent_workloads/README.md) for scope.

## Checked workload

Two sessions arrive at time zero. Session A contains three LLM calls across two
user turns; session B contains two calls. Input lengths are 32/64/96 and 48/80;
output lengths are 3/2/1 and 3/2. Four tool executions each take an assumed 2 ms,
with serial execution inside each step. A later user turn adds 1 ms think time.
Expected total: **5 LLM calls, 11 output tokens, 2 completed sessions**.

The small three-backend run uses `deepseek-decoder-fixture`, the archived
Nemotron hardware point selected by the existing model-validation runner,
static mapping, static batch size 1, a 0.1 s fixed window, and recomputed prompts.
The fixture is a small operator graph, not the full DeepSeek-V3 model.

| Local network backend | Completed calls / tokens | Call TTFT, excluding queue (ms) | Session A latency (ms) | Session B latency (ms) |
|---|---:|---:|---:|---:|
| HYDRA-Analytic | 5 / 11 | 0.0302 | 7.641 | 2.538 |
| HYDRA-Packet | 5 / 11 | 0.4236 | 9.290 | 4.323 |
| CHIPSIM/Garnet | 5 / 11 | 0.4236 | 9.290 | 4.323 |

Both packet paths completed all **2,102 local flows**, with zero inflight flows at
cutoff. Every call was released at its predecessor's completion plus the
specified external waits. All backends consumed identical normalized sessions,
hardware and static mappings. Packet/Garnet agreement here is a small smoke
result, not an accuracy claim across agent workloads.

A separate **full Qwen3-8B decoder** analytic replay of the same synthetic trace
completed all five calls. Session latencies were **990.649 / 882.052 ms**;
mean call TTFT excluding queue was **197.7542 ms**. A replay with the memory
auditor confirmed zero live request objects/reservations and resident weights
as the only remaining HBM contents.

## Correctness checks

- 114 tests discovered: **111 passed, 3 existing environment-gated CHIPSIM tests
  skipped**. The real CHIPSIM/Garnet smoke above ran separately and passed.
- Ten agent-specific tests cover nested turn parsing, explicit provenance,
  serial measured delays, malformed/unknown token counts, failed handler events,
  dependency timing, concurrent sessions, cutoff, one-token output, context
  rejection, and cross-backend detection of changed tool waits.
- The archived independent CSV fixture reproduced all serving metrics exactly.
- Fixed a pre-existing finished-token counter omission for prefill-only requests:
  one generated token must contribute one finished token. The agent fixture
  exercises this case in all three backends.
