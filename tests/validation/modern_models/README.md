# Modern text-decoder validation

Detailed reports and synthetic inputs are generated by the commands below;
only compact historical observations are retained here. New output belongs in
ignored `output_sanity_checks/` directories.

The model factory now accepts `qwen3-8b` and `qwen3.5-9b-text` on
HYDRA-Analytic, HYDRA-Packet and CHIPSIM. These are **experimental decoder-stack
performance models**, with shared analytical compute and different network
backends. No weights, inference engine or tokenizer are required.

The same runner supports `--packages N` for static contiguous layer partitioning
across copies of the selected package. See [multi-package validation](../multi_package/README.md)
for link parameters, capacity checks and complete-length DeepSeek examples.

| Model | Decoder blocks | Attention | Persistent state per sequence |
|---|---:|---|---|
| Qwen3-8B | 36 | GQA: 32 Q heads, 8 KV heads, head dim 128 | 2,048 KV bytes/token/layer |
| Qwen3.5-9B text | 32 | Repeating 3 Gated DeltaNet + 1 gated GQA; GQA 16 Q / 4 KV heads, head dim 256 | GDN: 2 MiB FP32 recurrent state + 32 KiB convolution state/layer; GQA: 2,048 KV bytes/token/layer |

Both use hidden size 4,096 and a 12,288-wide SwiGLU with all three projections.
Q/K normalization, rotary work, Qwen3.5 attention output gates, short depthwise
convolution, delta updates and gated output normalization have explicit profiles.
The pinned [official model configs](../../../docs/workload_modernization/model_inventory.json)
are checked by tests. Shapes were also checked against upstream
[Qwen3](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3/modeling_qwen3.py)
and [Qwen3.5](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_5/modeling_qwen3_5.py)
operator definitions. These code links are moving references; the config revisions
in the inventory are pinned.

## Execution contract

- Static batching with equal input/context lengths per batch, static mapping,
  pipeline parallelism; existing TSCS chiplets
  execute GQA blocks and MARCA chiplets execute recurrent blocks.
- One-byte weights, activations and KV, with GDN recurrent state counted at FP32.
  This is a performance assumption, **not a BF16 or quantization-quality claim**.
  Other precision settings and mapping/parallelism modes fail explicitly.
- `explicit-decoder-v1` profiles use serial roofline phases, decimal GB/s and
  nanoseconds. Weights stream once per batch; activation working sets that exceed
  SRAM spill. Attention assumes streaming causal reduction without a resident
  quadratic score matrix. GDN counts recurrent delta-rule work in both stages;
  it does not reproduce the scheduling of a chunked FLA/GPU prefill kernel.
- Embedding/LM-head execution and storage, vision, MTP/speculation, MoE routing,
  and tokenizer-specific prompt construction are outside this first version.
  Capacity and latency therefore describe the decoder stack, not the full model.
- These profiles need calibration before absolute hardware predictions or
  long-context claims. SRAM spill/reuse, nonlinear throughput, low-bit arithmetic
  and precision-dependent accelerator efficiency remain approximations.

Modern blocks use `memory_accounting_version=2`: prompt-sized prefill activations,
consistent MiB state-growth admission and context-limit rejection. Archived
LLaMA/Nemotron configs retain version 1 so their existing validation results are
not silently reinterpreted. The legacy native transfer timing convention and
TTFT recorder also remain; see the
[three-fidelity report](../packet_validation/README.md).

## Operator count checks

For batch size `B`, prompt length `L`, query heads `Hq`, head dimension `d`,
hidden size `D` and FFN width `I`, causal GQA prefill has
`2 * B * Hq * d * L * (L + 1) / 2` attention MACs; decode has
`2 * B * Hq * d * L`. Q/K/V projection widths are independent of `D`.
SwiGLU projections contribute `3 * B * L * D * I` MACs during prefill.
The GDN recurrence counts three state-matrix operations per token
(`3 * Hv * dk * dv` MACs), plus decay and elementwise delta work.
These formulas, parameter totals, KV growth, recurrent state and exported phase
latencies have regression tests using small independently counted geometries.

## Run

From the repository root, activate the HYDRA Python environment and build the
[Packet](../../../integrations/packet/README.md) and
[CHIPSIM](../../../integrations/chipsim/README.md) backends. Then:

```bash
python -m unittest tests.test_modern_models tests.test_execution_backend

python tests/validation/modern_models/validate.py \
  --output-dir output_sanity_checks/modern_models/smoke_new
```

When `--trace` is omitted, the runner generates its CSV in `--output-dir`.
The default smoke test uses two synthetic requests (32 input tokens and two
HYDRA decode iterations), batch size 2, a 0.4 s window, and the archived Nemotron
Chat P1 hardware design. That hardware is a reproducible control, not a Qwen
Pareto point. HYDRA counts the prefill transition as the first output token;
finishing this fixture produces six output tokens across two requests.

For faster development or a single model:

```bash
python tests/validation/modern_models/validate.py \
  --models qwen3.5-9b-text --backends hydra_sim hydra_packet \
  --output-dir output_sanity_checks/modern_models/hybrid_new
```

`--trace`, `--requests`, `--batch-size` and `--time-limit` select larger workloads.
Use `--batch-size 1` for heterogeneous traces: HYDRA currently profiles the first
request as the batch representative. Modern models reject unequal input/context
lengths within a static batch until an explicit ragged/padded batch profile is
available. Reusing an
existing Chat CSV replays its stored lengths; it does not make those lengths
Qwen-tokenized. Models reject requests whose full context plus decode iterations
exceed their configured context limit. The trace generator's own `max_tokens`
clipping remains a separate, recorded input setting.

Every run saves its exact command, model/precision/profile metadata, effective
workload, placement/mapping snapshot, metrics and process wall time. The runner
checks setup/workload/runtime equivalence across backends and requires nonzero
serving metrics. Use a fresh output directory for each invocation. CHIPSIM's gem5
may require permission to run outside restricted sandboxes.

## Measured smoke result

Measured 2026-10-04 using the default 0.4 s fixture. All six runs finished both
requests, emitted six HYDRA output tokens (15 tokens/s over this window), and
recorded two TTFT samples. All paired setup/runtime/workload comparisons passed.

| Model | Backend | TTFT (ms) | Process wall seconds |
|---|---|---:|---:|
| qwen3-8b | hydra_sim | 109.110 | 2.17 |
| qwen3-8b | hydra_packet | 109.356 | 8.48 |
| qwen3-8b | chipsim_contended | 109.356 | 392.26 |
| qwen3.5-9b-text | hydra_sim | 109.886 | 1.87 |
| qwen3.5-9b-text | hydra_packet | 110.180 | 7.58 |
| qwen3.5-9b-text | chipsim_contended | 110.180 | 355.16 |

Packet and CHIPSIM agree for this small fixture. Each has peak one active flow;
all 958 Qwen3 flows and 1,006 Qwen3.5 flows complete, with causal trace checks and
no in-flight flow at cutoff. **This is an execution smoke test, not contention,
capacity, or compute-calibration evidence.** Process times are single samples.
The runner generates comparison metrics, provenance and audits in `--output-dir`.

The final targeted suite passed 36 tests, including eight modern-model checks.
A separate unequal-length fixture (16/48 input tokens, batch size 1) also completed
on Analytic and Packet for both models. The legacy Nemo P1 control retained
TP 48 and TTFT 91.722/91.930 ms on Analytic/Packet after these changes.

## Extension points

- [Model configs](../../../Sim/config/modern_model_config.py): dataclass block and
  model subclasses, registered through `BaseModelConfig.create_from_name`.
- [Operator profiles](../../../analytic_profile/modern.py): independent GQA,
  SwiGLU and GDN subclasses through an operator factory. Both offline mapping
  and execution call `BaseAccModel.profile_kernel`, so they share costs.
- Blocks expose an `execution_family` and accelerator eligibility; the legacy
  `mamba`/`transformer` memory-group keys are compatibility names for recurrent
  and attention placement. GDN is not passed through the Mamba SSM kernel.

Agentic workload/session support is deferred. Calibration and precision/state
refinement remain necessary; initial KDA/MLA operator work is described below,
and the [Kimi decoder baseline](../kimi_models/README.md) now includes colocated
MoE with synthetic routes. Distributed experts and DeepSeek composition remain pending;
see the [feasibility report](../../../docs/workload_modernization/README.md).
